# Video Analyzer: система обробки відеоданих

Вебсервіс для автоматичної обробки відео: сегментація на сцени, розпізнавання мовлення,
виділення ключових слів. Результат повертається у вигляді структурованого JSON з таймкодами.

Проєкт розвивається в межах кваліфікаційної (бакалаврської) роботи
**"Інформаційна система обробки відеоданих на основі мікросервісної архітектури та нейромережевих моделей"**
(ЛНУ імені Івана Франка, факультет прикладної математики та інформатики).

## Гілки та версії

| Гілка / тег | Призначення |
|---|---|
| `main` | Стабільна версія. Базова реалізація, створена в межах курсової роботи (модульний моноліт). |
| `v1-coursework` | Тег, що фіксує стан проєкту на момент здачі курсової роботи. Використовується як бейзлайн для експериментів. |
| `microservices` | Розробка дипломної версії: розділення на мікросервіси, черга задач, PostgreSQL, об'єктне сховище, нові AI-компоненти. |

## Можливості

- Завантаження відео з локального файлу або за посиланням на публічний файл Google Drive.
- Перевірка кодека та контейнера (ffprobe), за потреби конвертація в H.264/MP4 (FFmpeg).
- Виявлення меж сцен: нейромережа TransNet V2 з гауссовим згладжуванням передбачень
  та адаптивним порогом; резервний алгоритм на гістограмах OpenCV.
- Розпізнавання мовлення: faster-whisper з резервним переходом на openai-whisper.
- Визначення мови тексту та виділення ключових слів для кожної сцени та для всього відео.
- Асинхронна обробка: запит одразу повертає `job_id`, стан задачі зберігається в SQLite.
- Експорт результатів у JSON та TXT, веб-інтерфейс українською мовою.
- Стійкість до помилок: відео без звуку, пошкоджені файли, недоступні посилання,
  перевищення ліміту розміру (HTTP 413).

## Архітектура поточної версії

Конвеєр обробки складається з етапів:

```
завантаження -> перевірка кодека -> нормалізація (FFmpeg)
            -> сегментація (TransNet V2 / OpenCV) + розпізнавання мовлення (Whisper)
            -> ключові слова -> об'єднання результатів
```

Усі етапи виконуються в одному процесі (модульний моноліт): фонові задачі через
`BackgroundTasks` FastAPI, стан задач в SQLite. Перехід до мікросервісної архітектури
виконується в гілці `microservices`.

## Технологічний стек

- Python 3.11, FastAPI, Uvicorn, Pydantic
- FFmpeg, OpenCV
- TransNet V2 (PyTorch), faster-whisper, openai-whisper
- SciPy (гауссове згладжування, пошук піків), langdetect, stop-words
- SQLite

> Рекомендована версія Python: 3.10 або 3.11. Версія 3.14 може бути несумісною з ML-залежностями.

## Запуск локально

Потрібні: Python 3.10-3.11 та встановлений [FFmpeg](https://ffmpeg.org/) (разом з `ffprobe`).

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python run_local.py
```

Сервіс буде доступний на `http://127.0.0.1:8000`, інтерактивна документація API
(Swagger UI) - на `http://127.0.0.1:8000/docs`.

## Запуск у Docker

```bash
docker build -t video-analyzer .
docker run --rm -p 8000:8000 \
  -v video_analyzer_storage:/app/storage \
  -v video_analyzer_models:/models \
  video-analyzer
```

Томи `storage` (завантажені та оброблені файли) і `models` (кеш завантажених ваг моделей)
зберігаються між запусками, тому моделі не завантажуються щоразу заново.
Перший запуск триває довше через завантаження ваг.

Перевірка: `curl http://localhost:8000/health`

## REST API

| Метод | Маршрут | Опис |
|---|---|---|
| POST | `/analyze` | Створює задачу (файл або посилання). Повертає `job_id`, статус 202 Accepted |
| GET | `/status/{job_id}` | Поточний стан задачі (`pending`, `processing`, `completed`, `failed`) |
| GET | `/result/{job_id}` | Результат: метадані, сцени з таймкодами, транскрипція, ключові слова |
| DELETE | `/job/{job_id}` | Видаляє задачу та пов'язані файли |
| GET | `/health` | Перевірка доступності сервісу та стану моделей |

Приклад:

```bash
curl -X POST http://localhost:8000/analyze -F "file=@lecture.mp4"
# {"job_id": "3273844d41d94ed7b7b8895c254dbdd3"}

curl http://localhost:8000/status/3273844d41d94ed7b7b8895c254dbdd3
curl http://localhost:8000/result/3273844d41d94ed7b7b8895c254dbdd3
```

## Обробка помилок

| Ситуація | Поведінка |
|---|---|
| Відео без аудіодоріжки | Сцени визначаються, транскрипція та ключові слова пропускаються |
| Пошкоджений або непідтримуваний файл | Задача переходить у стан `failed` з описом помилки |
| Недоступне або закрите посилання Google Drive | Задача `failed`, сервер продовжує працювати |
| Файл більше за ліміт (за замовчуванням 2 ГБ) | HTTP 413, задача не створюється |
| Недоступна модель TransNet V2 / faster-whisper | Автоматичний перехід на резервний алгоритм |
